# 類人猿ブロックパターン：LP向けパターン集
WordPressテーマ Snow Monkeyを拡張する「類人猿ブロックパターンプラグイン」のLP向けパターン集アドオンです

# 開発環境

Node.js のバージョンは [mise](https://mise.jdx.dev/) で管理しています（`mise.toml` で Node.js 24 を指定）。

当プラグインディレクトリーまで移動したあと、

- `mise install` で Node.js をインストール（初回のみ。`mise trust` を求められた場合は実行）
- `npm ci` でパッケージをインストール

# SCSSのコンパイル方法

- `npm run watch` でSCSSファイルの修正を常時監視（SCSSを修正したら即時CSSにコンパイルしてくれる）
- `npm run build` でCSS・JS・画像をビルド（コマンド走ったときだけコンパイル）

# 見た目の差分チェック

固定ページ（`rje_r002lp_*`）のフロント画面を Playwright で撮影し、基準画像と比較します（以前は BackstopJS を利用）。`npm start` で wp-env を起動した状態で実行してください。

- `npx playwright install chromium` でブラウザをインストール（初回のみ）
- `npm run test:visual:update` で基準画像を作成・更新（変更前の状態で実行。`tests/visual/__screenshots__` に保存され、Git には含めません）
- `npm run test:visual` で基準画像と比較（差分がある場合は `artifacts/visual-report` に差分画像を出力）

対象ページ・除外する要素は `tests/visual/scenarios.json`、画面幅（sp / md / lg / xg）は `tests/visual/playwright.config.js` で設定します。

# エディターの編集チェック（E2Eテスト）

各ブロックパターンがエディターで編集できるかを Playwright で確認します。`npm start` で wp-env を起動した状態で実行してください。

- `npx playwright install chromium` でブラウザをインストール（初回のみ）
- `npm run test:e2e:setup` でテスト用ユーザー（e2e-admin）を作成（初回のみ）
- `npm run test:e2e` でテストを実行（結果は `artifacts/playwright-report` に出力）

確認内容：

- ブロック検証エラー・未登録ブロック・未登録のブロックスタイルがないこと
- テキストを入力して保存でき、再読み込み後も壊れないこと
- 画像の差し替え・メディアの左右入れ替えをして保存でき、再読み込み後も壊れないこと

登録済みパターンと既存の固定ページ（`rje_r002lp_*`）の内容をコピーした一時的な下書きでテストし、終了後に削除します。元の固定ページは変更しません。

# composerの準備

当プラグインディレクトリーまで移動したあと、

- `composer install` でパッケージをインストール

# リリース手順

1. プラグインのルートファイル（`ruijinen-block-patterns-r002-lp.php`）の `Version` を上げ、README.md の「変更履歴」に同じバージョンの節（`## 3.2.2` など）を追加します
2. 作業ブランチを dev にマージすると、dev → main のリリースPRが自動作成（既存ならタイトル・本文を更新）されます
	- タイトルには `Version` が、本文（変更内容）には README.md の変更履歴の該当バージョンの節が使われます
3. リリースPRを main にマージすると、`Version` をタグ名としてリリースとzipが作成されます
	- 同じバージョンのタグが既に存在する場合、リリースはスキップされます（バージョンを上げ忘れた場合など）
	- リリースPRの本文がリリースノートになります
4. main の内容を dev へ反映するPRが自動作成されます
